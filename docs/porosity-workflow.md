# Porosity-to-performance workflow

Implemented 26 October 2026. This extends the saved material predictor with an
explicit porosity mapping and comparison of supplied structural/aerodynamic
results. It does not contain a solved bracket or wing model, and it has not
trained a new bracket/lift neural network.

**Current target correction, 27 October 2026:** CL means critical flaw length
(see `decisions.md` D19). The lift-related software described below predates
that correction and is retained as historical capability, not the current
project target. The 31 October section concerns a future porosity input to
the material stress-strain model.

## What is usable now

- Inspect which physical definitions are missing.
- Run a **conditional material study** after supplying a bulk-density/porosity
  interpretation, reference solid density, and shear-modulus-versus-porosity
  table. An assumed relation requires explicit acceptance and is labelled
  exploratory. The app neither pre-fills nor invents that relation.
- Use the existing model for all material-curve predictions. Interpolate G only
  between the supplied table points. Refuse mapped conditions outside the
  saved model's operating range, rather than silently extrapolating.
- Import actual solver-result CSVs and compare displacement, maximum stress and
  lift coefficient against a zero-porosity reference at matching conditions.
- Calculate aerodynamic CL only from supplied lift force, air density, speed
  and reference area: `CL = lift_N / (0.5 * rho_air * speed**2 * area)`.

These calculations are not independent validation of the submitted definitions
or solver results. No imported number is described as a newly solved result.
No material-curve output is used as a fabricated aerodynamic label.

## Required configuration

`configs/porosity_workflow.json` records the unresolved scientific definitions.
Its null/empty entries are intentional missing inputs, not physical defaults.
Before final predictions, obtain and record:

1. **Material/porosity:** density interpretation and reference density, pore
   fraction definition, a supported modulus relation, source stress units,
   stress/strain measures, initial state and the generating constitutive law.
2. **Bracket:** material law with needed elastic/plastic/damage properties,
   loads, support faces/bolts, contact behaviour, assembly placement, failure
   criterion, and a mesh-convergence check. Effective material transfer must be
   justified; the current fixed-path stress query is not a general multiaxial
   constitutive update.
3. **Aerodynamics:** wing/airfoil geometry, operating conditions and reference
   area, plus a demonstrated transfer from bracket deformation to the lifting
   surface. For a fixed rigid wing and fixed flow, an internal material change
   alone does not establish an aerodynamic CL change.

The sources and assumptions must be distinguishable. In particular, a
maximum structurally allowable lift coefficient is a different quantity from
the aerodynamic lift coefficient generated by the wing. Do not substitute one
for the other without agreeing the project target.

## Adding porosity to the planned Colab material model

Discussion recorded 31 October 2026. The user selected a fresh Colab notebook,
scikit-learn, one query MLP and `E11 -> Svm` for the material task. That notebook
is planned; it has not been created or trained in this discussion. Adding
porosity is a future option, not an instruction to change the delivered model.

**Later user instruction on 31 October:** assume porosity is **4%**, stored as
`porosity_fraction = 0.04` in `configs/study_assumptions.json`. Treat this as a
fixed nominal condition for the planned study and label it assumed. It does
not establish that the supplied histories were generated at 4% porosity.
Keep the constant in notebook/run metadata and retain the proposed five-input
MLP; adding the same phi to every training example cannot identify how stress
changes with phi. This choice does not set a reference density, density law,
G(phi), toughness or pore geometry. Establish applicable response data or a
supported physical mapping before claiming a stress prediction specifically
validated for 4% porosity. The two routes below remain future options for
learning or mapping a variable porosity input.

Porosity fraction is `phi = pore_volume / total_volume`; store 3% as `0.03`.
Each independent specimen or simulated microstructure needs a documented phi
value paired with its actual stress-strain history and material conditions.
Do not assign arbitrary phi values to copies of the same history.

There are two scientifically different routes:

- **Density-derived phi.** If the data owner confirms that `density` is bulk
  density and supplies an appropriate fully dense reference for the same
  material state, negligible pore mass gives
  `phi = 1 - density / reference_density`. A reference of 2700 would map the
  supplied density levels 2700, 2619 and 2488.05 to 0%, 3% and 7.85%. This is
  conditional arithmetic, not confirmation of those porosity labels.
  Replace density with phi in a newly fitted model rather than duplicating an
  exactly determined input. The proposed architecture remains 5-16-16-1,
  with 385 learned weights and biases. Alternatively, a prediction wrapper
  can convert phi back to density and use an existing model without refitting,
  provided the physical mapping and required G values are justified. Neither
  route introduces new pore physics into the supplied simulations.
- **Separately measured/simulated phi.** Obtain curves that genuinely vary with
  known phi while controlling or recording temperature, rate, material state
  and pore structure. If phi contains information beyond the other features
  and density retains a distinct physical meaning, add it as a sixth input:
  `[temperature, log10(strain_rate), density, shear_modulus, phi, E11] -> Svm`.
  A 6-16-16-1 starting architecture has 401 learned weights and biases. Fit
  fresh preprocessing and weights, then select settings on training cases.

Do not infer a shear-modulus/porosity law from the independent density/G levels
in the supplied matrix. If the interface accepts phi instead of both density
and G, it also needs a supported G(phi) relation. A scalar phi does not describe
pore size, shape, location or connectivity; control these or add measured
descriptors when they matter for the intended prediction.

For relabelling the same 73 cases, preserve `data/split.json`. For new related
curves, document a case/group split before fitting, keeping shared specimens
or source microstructures together and retaining the required 50/50 protocol.
Fit scalers inside training folds, report per-curve errors, and assess a
withheld porosity level using training-side diagnostics. Save the extended
model as a new version with its feature order, units, mapping source and
supported porosity range. New data is required for independent validation.

Primary references: [NIST porosity measurement study](https://doi.org/10.6028/jres.119.019)
compares density and imaging measurements and discusses the assumed dense
reference; [NIST pore-structure study](https://www.nist.gov/publications/investigation-pore-structure-cobalt-chrome-additively-manufactured-parts-using-x-ray)
documents different pore structures at similar porosities. Both studies concern
CoCr; they support the measurement/representation distinction, not an AlSi10Mg
reference density, modulus law or numerical performance claim.

## Solver-result contract

Download a CSV header from the workflow page. Required structural columns:

```text
case_id,independent_group_id,geometry_sha256,material_definition_id,load_case_id,source_reference,comparison_group_id,porosity_fraction,temperature_C,force_x_N,force_y_N,force_z_N,max_displacement_mm,max_von_mises_MPa
```

Optional aerodynamic columns must all be supplied together:

```text
aerodynamic_condition_id,aerodynamic_source_reference,lift_N,air_density_kg_m3,speed_m_s,reference_area_m2
```

- `source_reference` identifies the actual solved run or exported evidence.
  A file hash does not independently validate that run's physics.
- `independent_group_id` identifies related runs that must remain together in
  any later model's training/validation/test split.
- `comparison_group_id` identifies a controlled porosity study. Other material
  definitions, manufacturing state and loading protocol must be held controlled
  or explicitly documented. The software cannot prove that from result values.
- A zero-porosity baseline is used only when exactly one matching reference
  exists for the comparison group, geometry, load case, numerical loads,
  temperature and aerodynamic conditions. Ambiguous references are not chosen.
- Zero reference values produce no relative-percentage result. Negative or
  nonfinite structural magnitudes and invalid airspeed/density/area are rejected.
- Structural-only records never acquire an inferred CL value.

Command-line comparison preserves existing evidence:

```powershell
.\.venv\Scripts\python.exe src\porosity_workflow.py status
.\.venv\Scripts\python.exe src\porosity_workflow.py compare-results --csv path\to\actual-solver-results.csv --output reports\new-solver-comparison.json
```

No example CSV with fictitious bracket or aerodynamic values is supplied as
project results. Synthetic records exist only inside clearly labelled tests.
