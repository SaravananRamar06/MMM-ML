# Porosity-to-performance workflow

Implemented 26 October 2026. This extends the saved material predictor with an
explicit porosity mapping and comparison of supplied structural/aerodynamic
results. It does not contain a solved bracket or wing model, and it has not
trained a new bracket/lift neural network.

## Open the interface

From the project root in PowerShell:

```powershell
$env:MODEL_CHAT_PORT='8877'
.\.venv\Scripts\python.exe app\server.py
```

Open http://127.0.0.1:8877/workflow. The existing material predictor is available
at the same server's root URL. Port 8877 permits using the new workflow while an
earlier Studio instance is running on 8766. Keep the terminal open; Ctrl+C stops
the server.

## What is usable now

- Inspect which physical definitions are missing.
- Run a **conditional material study** after supplying a bulk-density/porosity
  interpretation, reference solid density, and shear-modulus-versus-porosity
  table. An assumed relation requires explicit acceptance and is labelled
  exploratory. The app neither pre-fills nor invents that relation.
- Use the existing model for all material-curve predictions. Interpolate G only
  between the supplied table points. Refuse mapped conditions outside the
  saved model's operating range, rather than silently extrapolating.
- Import actual solver-result CSVs and compare displacement, maximum stress and
  lift coefficient against a zero-porosity reference at matching conditions.
- Calculate aerodynamic CL only from supplied lift force, air density, speed
  and reference area: `CL = lift_N / (0.5 * rho_air * speed**2 * area)`.

These calculations are not independent validation of the submitted definitions
or solver results. No imported number is described as a newly solved result.
No material-curve output is used as a fabricated aerodynamic label.

## Required configuration

`configs/porosity_workflow.json` records the unresolved scientific definitions.
Its null/empty entries are intentional missing inputs, not physical defaults.
Before final predictions, obtain and record:

1. **Material/porosity:** density interpretation and reference density, pore
   fraction definition, a supported modulus relation, source stress units,
   stress/strain measures, initial state and the generating constitutive law.
2. **Bracket:** material law with needed elastic/plastic/damage properties,
   loads, support faces/bolts, contact behaviour, assembly placement, failure
   criterion, and a mesh-convergence check. Effective material transfer must be
   justified; the current fixed-path stress query is not a general multiaxial
   constitutive update.
3. **Aerodynamics:** wing/airfoil geometry, operating conditions and reference
   area, plus a demonstrated transfer from bracket deformation to the lifting
   surface. For a fixed rigid wing and fixed flow, an internal material change
   alone does not establish an aerodynamic CL change.

The sources and assumptions must be distinguishable. In particular, a
maximum structurally allowable lift coefficient is a different quantity from
the aerodynamic lift coefficient generated by the wing. Do not substitute one
for the other without agreeing the project target.

## Solver-result contract

Download a CSV header from the workflow page. Required structural columns:

```text
case_id,independent_group_id,geometry_sha256,material_definition_id,load_case_id,source_reference,comparison_group_id,porosity_fraction,temperature_C,force_x_N,force_y_N,force_z_N,max_displacement_mm,max_von_mises_MPa
```

Optional aerodynamic columns must all be supplied together:

```text
aerodynamic_condition_id,aerodynamic_source_reference,lift_N,air_density_kg_m3,speed_m_s,reference_area_m2
```

- `source_reference` identifies the actual solved run or exported evidence.
  A file hash does not independently validate that run's physics.
- `independent_group_id` identifies related runs that must remain together in
  any later model's training/validation/test split.
- `comparison_group_id` identifies a controlled porosity study. Other material
  definitions, manufacturing state and loading protocol must be held controlled
  or explicitly documented. The software cannot prove that from result values.
- A zero-porosity baseline is used only when exactly one matching reference
  exists for the comparison group, geometry, load case, numerical loads,
  temperature and aerodynamic conditions. Ambiguous references are not chosen.
- Zero reference values produce no relative-percentage result. Negative or
  nonfinite structural magnitudes and invalid airspeed/density/area are rejected.
- Structural-only records never acquire an inferred CL value.

Command-line comparison preserves existing evidence:

```powershell
.\.venv\Scripts\python.exe src\porosity_workflow.py status
.\.venv\Scripts\python.exe src\porosity_workflow.py compare-results --csv path\to\actual-solver-results.csv --output reports\new-solver-comparison.json
```

No example CSV with fictitious bracket or aerodynamic values is supplied as
project results. Synthetic records exist only inside clearly labelled tests.

## Future bracket/lift surrogate

After verified solver data exists, evaluate a second compact tabular MLP against
simple baselines for the defined geometry and load family. Inputs and targets
must follow the actual physics and available labels; retain training-only input
and target scaling, whole-source grouping, the required case split, and an
additional withheld porosity/load-condition evaluation. Do not choose an
architecture or report its accuracy before those data exist. A surrogate of
FEA/CFD remains a surrogate of that calculation, not experimental validation.

## Verification

Run unit checks and, while the server is running, both live suites:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
$env:MODEL_CHAT_PORT='8877'
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'live_*check.py' -v
```

The fresh raw-data audit established source-hash identity, 2,197,000 finite
rows, exact raw-derived test targets, and training-only input/target scalers.
Delivered-model test mean curve RMSE is 0.05908515 source units. A separate
frozen-settings Windows fit gave 0.11260308, with no warnings but differing
weights/predictions. Saved-artifact inference is repeatable; exact training
portability is unresolved. None of the delivered model files were replaced.
